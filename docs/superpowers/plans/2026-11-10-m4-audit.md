# SecureDB Vault — Milestone 4 (Audit log) Plan

**Goal:** A per-tenant, hash-chained, append-only audit log written in the same transaction
as every vault operation, with list and verify endpoints.

**Spec:** §2.6 (audit entry per request), §2.7 (chain, advisory lock, grants, verify), §3
(`audit_log`), §4.1 (`GET /v1/audit`, `GET /v1/audit/verify`), §4.3 (`verify-audit`).
**Builds on:** M3 (`feat/m3-vault-core`), stacked branch `feat/m4-audit`.
Compact plan (see M3 execution note).

## Decisions

| # | Decision | Why |
|---|---|---|
| A1 | `hash = SHA256(prev_hash ‖ canonical_json(entry))`; genesis `prev_hash` = 32 zero bytes; canonical JSON = sorted keys, no whitespace, UTF-8; `ts` is generated in Python (UTC, µs) and is part of the hashed entry | Deterministic and reproducible by anyone with the rows. |
| A2 | Appends take `pg_advisory_xact_lock(<64-bit int from tenant uuid>)` then read the head row | Serialises appends per tenant without blocking other tenants; lock is released at commit/rollback. |
| A3 | App role gets only `SELECT, INSERT` on `audit_log`; FORCE'd RLS; PK `(tenant_id, seq)` | Spec §2.7; an app compromise cannot rewrite history. |
| A4 | Verify recomputes every hash, checks `seq` is contiguous from 1 and each `prev_hash` links; returns the first broken `seq`. Optional anchor `(seq, hash)` | Detects edits, middle deletions and reordering by anyone who cannot rewrite every later hash. The chain is unkeyed, so **truncation of the newest entries and a full rewrite by the table owner are only detectable against an anchor** kept outside the database (`anchor_seq`/`anchor_hash` on the API and CLI). |
| A5 | Entries contain token IDs, types, counts and outcomes — never values | Erasure (M5) never breaks the chain and the log is not a PII store. |
| A6 | Successful operations are audited inside the operation's transaction (both commit or neither). Rejected tokenize requests (403/422) are audited in a separate transaction so the rejection is recorded even though the operation rolls back | "Every access is written to a tamper-evident audit log." |
| A7 | Actor: `api_key` (+ key id) for API calls, `system` (+ `cli`) for operator commands. `request_id` comes from the structlog context bound by the request middleware | Spec §3 `actor_type`. |
| A8 | `GET /v1/audit` uses keyset pagination on `seq` (`cursor`, `limit` ≤ 200) with optional `action`, `from`, `to` filters; both endpoints need scope `audit:read` | Spec §4.1. |

## Tasks

1. **Migration 0004 + model** `AuditLog`. Tests: RLS isolation, app role cannot UPDATE/DELETE, PK uniqueness.
2. **`securedb/audit/log.py`** — `Actor`, `append(session, tenant_id, actor, action, token_ids, outcome) -> AuditRecord`, `verify(session, tenant_id) -> VerifyResult(ok, entries, head_hash, first_broken_seq)`, `list_entries(...)`. Tests: chain links, genesis, concurrent appends produce contiguous seq (threads), verify detects edited outcome / deleted middle row / swapped rows (via owner role), canonical JSON stability, request_id captured.
3. **Wire into operations** — TokenService (tokenize/detokenize/delete), API-key issue/revoke, set_policy, create_tenant. Rejected tokenize audited separately in the router. Tests: each operation leaves exactly the expected entry; entries never contain values; rollback leaves no entry.
4. **API** — `GET /v1/audit`, `GET /v1/audit/verify`. Tests: scope, pagination, filters, verify ok/broken.
5. **CLI** — `verify-audit --tenant`. Test: ok and broken exit codes.

## Review outcome

Fresh whole-branch review: 0 Critical, 4 Important + 1 Minor re-graded to Important (all fixed test-first), 10 Minor (deferred).

Fixed:
1. `verify` buffered the whole log (yield_per applied after execution): now streams via a server-side cursor; test asserts `stream_results`.
2. Floats in outcomes would be re-rendered by JSONB and trigger false tamper alarms (and NaN/Infinity would 500): outcomes now accept only str/int/bool/None/lists/string-keyed dicts.
3. Guarantee wording: the chain is unkeyed, so tail truncation **and full rewrites by the table owner** need an external anchor. `verify` accepts `(anchor_seq, anchor_hash)` on the API and CLI; tests show both attacks are missed without and caught with an anchor.
4. Added the spec's reorder tamper test.
5. (re-graded) `actor` was optional and defaulted to "cli", which would misattribute console actions in M6: it is now a required keyword on every audited operation.

Deferred minors: `set_policy` takes the audit lock before its write (harmless, but breaks the "row work first, append last" convention); no `lock_timeout`/`statement_timeout` so a hot tenant can hold pool connections; failed detokenize (CryptoError) is not audited; scope-denied and schema-invalid requests are not audited and a failed rejection-append returns 500; API timestamps use the DB session timezone (canonical form is UTC µs); verify-audit prints "head None" for an empty log and unlocks the master key it does not need; no index for action/time filters; no CHECK on hash lengths; operator-chosen API key names are permanent in the log.
