# SecureDB Vault — Milestone 7 (Polish) Plan

**Goal:** AWS KMS key provider, demo data, documentation and repository polish.
**Spec:** §2.4 (AwsKmsKeyProvider), §4.3 (`seed-demo`), §7 (docs, ADRs, SECURITY, LICENSE, README).
**Builds on:** M6 (`feat/m6-console`), branch `feat/m7-polish`. This branch also carries the
fixes from the M6 review.

## Decisions

| # | Decision | Why |
|---|---|---|
| P1 | KMS provider takes an injected client and is tested against an in-memory fake, not `moto`; `boto3` is an optional extra (`securedb[kms]`) | Keeps the default install and test run free of a large cloud SDK; the provider is ~40 lines over two KMS calls. Spec said `moto`. |
| P2 | Wrap context is passed as the KMS encryption context | KMS itself then refuses a wrong-tenant unwrap, and CloudTrail records the context. |
| P3 | `seed-demo` prompts for the demo console password and prints API keys and TOTP links once | No default credentials anywhere in the repository. |
| P4 | CI coverage gate widened to `crypto`, `vault`, `policy`, `audit` (>= 90%) | Spec §6. |
